# 图片分享社区（微信云开发）

一个基于微信小程序 + 云开发的图片分享社区示例，实现社区帖子流、发帖(文字+图片)、点赞/收藏/分享、个人主页与底部 Tab 导航。

## 功能

- 底部固定导航：左「社区」、右「个人主页」。
- 点头像登录（`chooseAvatar` 获取微信头像 + 昵称输入），头像上传云存储。
- 社区帖子流：头像昵称、正文、图片九宫格、点赞 / 收藏 / 分享（带实时数字）。
- 右下角**可拖动**的发帖按钮。
- 发布帖子页：正文 + 多图(≤9)上传。
- 个人主页：头像昵称登录、**独立照片相册（九宫格）**、发布新帖、我的帖子列表。
- 照片相册与帖子分开：相册单独上传图片，与帖子内容互不相混。
- 他人主页：点头像进入查看 TA 的动态。

## 云环境准备（重要，需在开发者工具中手动完成）

### 1. 创建集合 `posts` 与 `photos`

在「云开发控制台 - 数据库」依次创建两个集合：

- **`posts`**：权限设置为 **「所有用户可读，仅创建者可读写」**
  （社区 / 个人主页 / 他人主页都要读取他人的帖子，故须所有人可读。）
- **`photos`**：相册集合（图片只存在个人主页本人查看与上传，可保持默认权限）。

### 2. 部署云函数

分别右键以下目录 →「上传并部署：云端安装依赖」：

- `cloudfunctions/getOpenid` ：返回调用者 openid。
- `cloudfunctions/postOps` ：点赞 / 取消点赞 / 收藏 / 取消收藏 / 分享计数（服务端维护 `posts` 的 `likedBy`、`favedBy` 数组与计数）。

> 点赞身份采用「身份 key」：登录用户 `u_<openid>`、游客 `g_<本地会话id>`。因此登录与游客的点赞记录互不可见（数据不互通），但都用同一 `likedBy` 数组，故点赞**总数互通**。**改动后务必重新上传部署 `postOps`**。

### 3. 数据库结构

`posts`（帖子）集合一条记录示例：

```json
{
  "_openid": "发布者openid",
  "nickName": "昵称",
  "avatarUrl": "云存储fileID",
  "region": "省市",
  "content": "正文",
  "images": ["云存储fileID1", "..."],
  "likedBy": ["openid..."],
  "favedBy": ["openid..."],
  "likeCount": 0,
  "favCount": 0,
  "shareCount": 0,
  "addDate": "YYYY-MM-DD HH:mm:ss"
}
```

`photos`（相册）集合一条记录示例：

```json
{
  "_openid": "发布者openid",
  "fileID": "云存储fileID",
  "addDate": "YYYY-MM-DD HH:mm:ss"
}
```

> 点赞/收藏因受数据库权限限制，必须经云函数 `postOps` 在服务端修改，前端不要直接改他人帖子的数组字段。
