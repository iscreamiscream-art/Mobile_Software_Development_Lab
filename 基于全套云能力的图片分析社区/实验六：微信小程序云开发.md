# 一、实验内容

## 一、实验目的

1. 综合应用微信小程序云开发的基础知识，完成图片分享社区小程序的开发，实现图片上传、全量图片展示、个人作品查看、图片下载、分享、全屏预览等核心业务功能。
2. 掌握云开发三大核心能力的使用：云数据库的集合创建、权限配置与数据增删查改，云存储的文件上传与下载管理，云函数的创建、部署与调用。
3. 熟悉小程序页面开发流程，掌握WXML页面结构、WXSS样式设计、JS逻辑交互的协同开发方式，理解页面间参数传递与数据通信的实现方法。

## 二、实验步骤

### 一、项目初始化

#### 1. 创建并清理云模板项目
1. 新建空白文件夹（工程根），用微信开发者工具「导入」该文件夹，填写 AppID `wxda4913ae5e6cf25b`，选择「小程序·云开发」模板创建项目。
2. 清理默认模板代码：
   - 删除默认 `cloudfunctions/quickstartFunctions`（及 `login` 等演示云函数）；
   - 修改 `app.json`，`pages` 仅保留 `pages/index/index`；
   - 删除 `pages` 下 `index` 以外的演示页面目录；
   - 清空 `index` 页 JS/WXML/WXSS 默认代码，JS 中写入 `Page({})` 基础结构；
   - 清空 `app.wxss` 默认样式；
   - 删除模板 `images`、`style`、`components` 中的演示资源。
3. 在 `project.config.json` 中确认根目录划分：
   - `"miniprogramRoot": "miniprogram/"`（小程序端）
   - `"cloudfunctionRoot": "cloudfunctions/"`（云函数端）

#### 2. 部署云数据库（集合与权限）
在「云开发控制台 → 数据库」依次创建两个集合：
- **`posts`**：帖子集合。权限设为「所有用户可读，仅创建者可读写」。社区、个人主页、他人主页都要读他人帖子，故必须所有人可读。
- **`photos`**：个人照片相册集合。仅供本人查看上传，可保持默认（仅创建者可读写）权限。

`posts` 单条记录结构（关键字段）：
```json
{
  "_openid": "发布者openid",
  "nickName": "昵称", "avatarUrl": "云存储fileID", "region": "省市",
  "content": "正文", "images": ["云存储fileID", "..."],
  "likedBy": ["身份key"], "favedBy": ["身份key"],
  "likeCount": 0, "favCount": 0, "shareCount": 0, "viewCount": 0,
  "addDate": "YYYY-MM-DD HH:mm:ss"
}
```
`photos` 单条记录：`{ _openid, fileID, addDate }`。

#### 3. 部署云函数
分别右键以下目录 →「上传并部署：云端安装依赖」：
- `cloudfunctions/getOpenid`：返回调用者 openid（用于获取用户身份）。
- `cloudfunctions/postOps`：服务端统一维护点赞/取消、收藏/取消、分享、浏览计数（写入 `likedBy`、`favedBy` 数组并用 `db.command.addToSet/pull/inc` 原子更新），前端不直接改他人帖子的数组字段。

> 点赞/收藏身份采用「身份 key」：登录用户 `u_<openid>`、游客 `g_<本地会话id>`，登录态与游客态互不互通，但数组同一份故总数互通。

#### 4. 注册多页面与底部导航
在 `app.json` 的 `pages` 数组中追加页面路径，开发者工具自动生成对应 JS/JSON/WXML/WXSS：
```
pages/index/index     社区(帖子流)
pages/mine/mine       个人主页
pages/publish/publish 发帖
pages/homepage/homepage 他人主页
pages/detail/detail   帖子详情
pages/mycollect/mycollect 我的喜欢/收藏
```
配置全局 `window`（导航标题「图片分享社区」、背景色）与 `tabBar`：左侧「社区」跳 `index`，右侧「个人主页」跳 `mine`。

### 二、页面视图设计

按页面逐个编写 `.wxml/.wxss/.js`，统一视觉风格（卡片、九宫格、操作条）：
- **社区页 `index`**：帖子列表卡片（作者头像/昵称/地区、正文、图片九宫格、点赞❤/收藏★/分享↗带实时计数、时间）；右下角**可拖动**发帖浮动按钮（短按进发布页）。
- **发帖页 `publish`**：顶部发布者信息，正文 `textarea`（≤500字）+ 图片选择九宫格（≤9张、可预览/删除），底部「发布」按钮，提交带 loading。
- **个人主页 `mine`**：资料卡（点头像 `chooseAvatar` 登录、填昵称、签名、可换背景图）、统计条（我的喜欢/收藏/浏览）、**独立照片相册**（单独上传，与帖子分离）、我的帖子列表（含删除）。
- **详情页 `detail`**：单帖大图九宫格 + 完整操作条 +「下载图片」。
- **他人主页 `homepage`**：点头像进入，展示 TA 的资料与 TA 的动态（只读）。
- **我的喜欢/收藏页 `mycollect`**：按类型展示我点赞/收藏过的帖子。

### 三、核心逻辑实现

- **登录与资料**：点头像走 `chooseAvatar` 取头像、`type="nickname"` 输入昵称，头像传云存储，写入 `users`；未登录用户以游客身份浏览（身份 key 为本地会话 id）。
- **帖子发布**：`publish` 页 `wx.chooseMedia` 选图 → `cloud.uploadFile` 上传云存储得到 fileID → 写 `posts` 集合并带 addDate。
- **数据读取**：`index`/`mine`/`homepage`/`detail`/`mycollect` 通过 `db.collection('posts')`（`where`/`orderBy('addDate','desc')`/`get`）加载，图片用云存储 fileID 直接渲染。
- **点赞/收藏/分享/浏览**：统一调 `postOps` 云函数，传 `{ postId, action, userKey }`，由服务端原子更新并返回最新帖，前端即时刷新计数与高亮态。
- **相册**：`mine` 页独立选择上传图片写 `photos` 集合，九宫格展示，长按删除。
- **分享**：按钮 `open-type="share"` 并实现 `onShareAppMessage`，分享计数通过 `postOps` +1。

### 四、功能测试（联调验证）

1. 冷启动进入「社区」，应能看到数据库中的帖子流与空态提示。

2. 游客在首页点头像/点收藏/分享应被引导登录；登录后头像昵称正确展示。

3. 发布正文+多图 → 社区列表实时刷新出该帖；刷新后仍在。

4. 自己点自己帖子点赞/收藏：次数 ±1、图标高亮切换正确。

5. 用另一身份查看同一帖子：点赞数互通；进「我的喜欢/收藏」看到记录。

6. 个人主页上传相册照片与发帖，二者互不相混；点头像进他人主页仅见他人动态。

7. 详情页可预览、下载图片；分享回跳正常。

8. 在数据库 `posts`/`photos` 核对字段、权限与计数一致性。
