# 一、实验内容

## 一、实验目的

1、综合运用微信小程序开发知识，完成完整推箱子小游戏项目，掌握小程序页面创建、页面跳转、事件绑定等基础开发能力。
2、熟练掌握小程序 <canvas> 画布组件以及绘图相关 API，能够使用drawImage、clearRect等接口完成游戏地图绘制。
3、理解二维数组存储游戏地图数据的思想，掌握游戏逻辑开发：人物移动、箱子推动、胜利条件判断、关卡重置。
4、熟悉小程序项目完整开发流程：项目创建、文件整理、素材导入、页面布局样式、公共数据模块封装、页面间参数传递。
5、理解选关首页与游戏页面之间的数据传递，掌握require引入公共 js 模块、wx.navigateTo页面跳转、dataset 传递参数。

## 二、实验步骤

1. **创建小程序项目** 打开微信开发者工具，新建空白小程序项目，项目名称设置为`boxGame`，开发模式选择小程序，不使用云服务，语言选择JavaScript。下载实验提供的游戏图片素材压缩包，保存备用。
2. 项目页面文件配置
   1. 修改`app.json`文件，配置`pages`属性，添加`pages/index/index`与`pages/game/game`，保存文件后工具自动生成game页面目录。
   2. 清理项目默认文件：删除原有`utils`文件夹、`pages/logs`目录；清空`index.wxml`、`index.wxss`、`index.js`、`app.wxss`、`app.js`全部原有代码。
   3. 在`index.js`自动补全`Page()`函数；在`app.js`自动补全`App()`函数。
   4. 在项目根目录新建`images`文件夹（存放图片资源）、`utils`文件夹（存放公共js脚本）。
   5. 将关卡预览图片复制到`images`文件夹；在`images`内新建`icons`子文件夹，放入墙、地板、主角、箱子、终点图标素材。
   6. 在`utils`文件夹新建`data.js`文件，定义4套8×8二维数组地图`map1~map4`，数字代表地图元素：1为墙、2为地板、3为终点、4为箱子、5为人物、0为外围；使用`module.exports`导出`maps`数组供其他页面调用。
3. 编写全局样式与首页页面布局
   1. 修改`app.json`中`window`配置项，自定义导航栏背景色与导航栏标题文本。
   2. 编辑`app.wxss`编写全局公共样式，设置页面容器、标题样式。
   3. 编写首页`pages/index/index.wxml`：编写页面容器、标题，使用`wx:for`循环渲染关卡列表，`image`展示关卡预览图，`text`展示关卡序号。
   4. 编写首页`pages/index/index.wxss`：设置关卡列表、关卡条目、图片样式，实现两列布局。
   5. 编写首页`pages/index/index.js`：在`data`定义关卡图片数组；给关卡条目绑定`bindtap`点击事件，通过`data‑level`传递关卡下标；实现`chooseLevel`点击函数，调用`wx.navigateTo`跳转到游戏页面，url携带关卡level参数。
4. 编写游戏页面布局样式
   1. 编写`pages/game/game.wxml`：添加关卡标题文本、`<canvas canvas‑id="myCanvas">`画布组件；编写上下左右4个方向按钮、重新开始按钮，为所有按钮绑定对应的点击事件。
   2. 编写`pages/game/game.wxss`：设置画布宽高边框、方向按键布局、按钮尺寸与边距。
   3. 在开发者工具添加自定义编译模式，启动页面设置为`pages/game/game`，启动参数填写`level=0`，用于单独调试游戏页面。
5. 实现游戏页面业务逻辑
   1. 在`game.js`文件顶部使用相对路径`require('../../utils/data.js')`引入关卡地图数据。
   2. 定义全局变量：地图图层`map`、箱子图层`box`、方块宽度`w`、记录主角位置的行变量`row`、列变量`col`。
   3. 实现页面生命周期`onLoad(options)`：接收首页传递的level参数，更新页面关卡编号；获取canvas绘图上下文；调用`initMap()`初始化地图数据；调用`drawCanvas()`绘制游戏画布。
   4. 编写`initMap(level)`初始化地图函数：读取对应关卡原始地图，双重循环解析二维数组，分离地图、箱子数据，记录主角初始行列坐标。
   5. 编写`drawCanvas()`画布绘制函数：清空画布，双重循环绘制8×8地图格子，叠加绘制箱子、游戏主角，执行`ctx.draw()`完成画布渲染。
   6. 编写方向控制函数`up()`、`down()`、`left()`、`right()`：做边界判断；判断前方是否为墙体；空地直接移动主角；前方为箱子时判断是否可以推动，更新箱子和主角坐标；每次移动完成刷新画布，调用胜利判断函数。
   7. 编写`isWin()`胜利判断函数：遍历整个8×8地图，校验所有箱子是否全部位于终点位置。
   8. 编写`checkWin()`函数：调用胜利判断函数，游戏胜利时使用`wx.showModal`弹出成功提示弹窗。
   9. 编写`restartGame()`重新开始函数：调用`initMap()`重置当前关卡地图数据，重新绘制画布，恢复游戏初始状态。
6. 项目整体功能测试
   1. 将编译模式切回普通编译，从首页开始测试项目。
   2. 首页测试：4个关卡正常渲染，点击关卡能够跳转到游戏页面，关卡编号显示正确。
   3. 游戏功能测试：地图绘制正常；方向键控制人物移动、推动箱子功能正常；全部箱子推至终点弹出成功提示；点击重新开始按钮恢复关卡初始状态；切换不同关卡验证地图加载正常。
7. **调试排错** 检查图片路径、`canvas‑id`名称、js文件相对引用路径、数组下标、边界判断逻辑，修改代码错误，完成实验。

# 二、问题总结与体会

描述实验过程中所遇到的问题，以及是如何解决的。有哪些收获和体会，对于课程的安排有哪些建议。

**1. 步数用尽后的状态"卡死"问题**

当步数减到 0 弹出失败弹窗后，方向键仍可能响应，出现"游戏结束了还能动"的 bug。我引入了 `gameOver` 标志位，并在所有移动、技能入口处统一判断：`if (this.gameOver || this.data.steps <= 0) return`，同时弹窗确认后自动重新加载本关，彻底解决了卡死问题。

**2. 破墙技能的边界情况**

破墙技能设计了"蓄力—破墙"两步交互，但一开始边缘的墙也可以被打破，导致人物走出地图范围。后来我在 `breakWall` 中增加了**边缘墙体判断**：只有不与 0（外围）相邻的墙体才能破除，并保证只能破除相邻一格，同时通过 `skillUsed` 标志实现"一局只能用一次"。
